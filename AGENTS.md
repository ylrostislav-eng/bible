# Правила работы в репозитории

## Git и завершение разработки

- После каждого логически законченного блока разработки сначала проверить
  итоговые изменения и запустить все релевантные тесты, typecheck, lint и
  build, если такие команды предусмотрены проектом.
- Если все обязательные проверки прошли успешно, создать осмысленный Git
  commit и выполнить `git push` в текущую ветку.
- Не отправлять в репозиторий заведомо сломанное или незавершённое состояние.
- Не переключать ветки и не выполнять force push без прямого разрешения
  владельца проекта.
- Ветка `claude/telegram-bible-quiz-setup-y25ncc` подключена к Railway
  Production. Каждый push в неё автоматически запускает production deployment,
  поэтому перед отправкой обязательно убедиться, что завершён весь блок работ
  и проверки успешны.
- После push сообщить владельцу hash коммита и перечень выполненных проверок.
